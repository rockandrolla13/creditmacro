## The one architectural decision already made

V4 §9.1 requires KnowledgeState to be consulted BEFORE hypotheses are generated. This repo's
memory firewall requires history to be read only AFTER the freeze. Both are written down;
they appear to contradict. The resolution, decided 2026-08-11 and already implemented:

    HISTORY MAY SET THE AGENDA. IT MAY NOT SUPPLY THE ANSWER.

`engine/memory.py::MemoryRetriever.coverage()` returns `CoverageEntry` — slug, type, status,
source count, updated — and never a conclusion. It is readable in phase A and is **not** a
back door: after calling it, every case slug still refuses. `COVERAGE_FIELDS` pins the field
set so a conclusion-bearing field fails a test rather than widening what phase A sees.

Task 2.1 builds KnowledgeState **on that view and only that view**. Any task that reads case
page bodies, or adds a phase-A escape hatch to the retriever, has failed regardless of
whether its tests pass.

  anywhere, in any docstring or example.

- Every task creates files under `engine/research/` and `tests/unit/`. Create
  `engine/research/__init__.py` if it does not exist; it is the only file more than one task
  may touch, and each task appends its own export line rather than rewriting the file.
